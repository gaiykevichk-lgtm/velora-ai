# Подтверждение покупки — 2026-11-05

Пользователь разрешил публикацию в существующий Render service. Контрольную реальную оплату проводит пользователь; фиктивные оплаченные заказы в production не создаём.

## Реализация
- Оригинальный утверждённый PDF сохранён как artwork в assets/invoices/template.pdf; удалены только переменные надписи. pdf-lib заполняет его, встроенный шрифт поддерживает Unicode.
- Новые карточные счета получают TU-год-последовательность из существующей bank_seq под блокировкой заказа; номер сохраняется в payment_orders.invoice_number. Существующие банковские номера INV не меняются.
- Карточный buyer_name запрашивается при checkout и сохраняется в заказе. Для старых заказов без имени отображается email, имя не придумывается.
- Ссылка письма ведёт на owner-only API счёта. Без сессии — переход на вход с разрешённым returnTo; после входа открывается тот же счёт.
- Задание purchase_receipt_outbox создаётся в транзакции начисления. Отправка после COMMIT; ошибка письма не откатывает оплату и баланс. Старое дополнительное банковское письмо заменено единым receipt.
- Resend использует стабильный Idempotency-Key. Первое содержимое сохраняется в outbox.payload для идентичного повтора.
- POST /api/payments/receipt: отдельный повтор только для владельца/администратора и credited заказа; уже отправленные сообщения не отправляются повторно. Повторы ограничены 23 часами с первой попытки (внутри 24-часового окна Resend); после окна требуется ручная сверка доставки. Зависшее sending можно повторить после двух минут. Баланс этот route не изменяет.
- Кнопки Retry failed receipt email добавлены у оплаченных заказов обоих способов.
- Paid, Total paid и подтверждение начисления скрыты для неоплаченного банковского инвойса. Налоговые ставки/суммы не добавляются. VAT FR81107643348 остаётся постоянным.

## Настройки
DATABASE_URL, RESEND_API_KEY, SMTP_FROM, APP_BASE_URL и действующие INFINI_* / BANK_*; значения секретов в документацию не записываются.

## Проверки
TypeScript; npm test (60 тестов); PDF перечитан pypdf и отрендерен, изображение просмотрено. Техническое письмо (не receipt и не фиктивная покупка) на contact@omnix-21.com принято Resend API HTTP 200, message id 01a1ac13-0d1c-7510-86f3-3c81af5bf54c. Это подтверждает приём сервисом, не факт попадания во входящие.

## Ограничения
Референс карты — проверенный provider_order_id Infini из оплаченного заказа. Иные идентификаторы транзакций API не выдумываются. Полный реальный путь с банковской картой проверяется после платежа пользователя.
