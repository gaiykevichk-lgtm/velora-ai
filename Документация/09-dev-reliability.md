# Надёжность: работа в development

Запрос: исправить пункты 1–6 без публикации. Production и реальные платежи не изменяются. Стек: Next.js, PostgreSQL; dev-проверки могут использовать только изолированную тестовую базу. Приоритет: видео и резервирование токенов, история, форматы, вход, Infini. Подтверждённые проблемы в исходном коде: история не загружается при выборе проекта, сессия не восстанавливается при загрузке студии; видео обновляется только по запросу клиента, токены списываются при отправке. Полноценная серверная обработка видео потребует надёжного фонового воркера и сохранного хранилища; нельзя заменить их зависимостью от открытой вкладки.

## Статус реализации (пункты 1–6), 2026-10-29
Всё сделано в коде и проверено только на тестовой БД (pg-mem) и локальном mock-провайдере; production и реальные платежи не менялись.

- **Видео:** задание проходит queued → processing → completed/failed. Статус обновляет сам сервер (`instrumentation.ts`, опрос каждые 20 с, плюс проверка при чтении истории), а не открытая вкладка. Готовый файл скачивается у провайдера и хранится в таблице `run_media`; выдаётся владельцу через `/api/media?runId=…` (Range, `&download=1`). ID задания и причина ошибки пишутся в серверный лог (`[video]`). Тайм-аут `VIDEO_TIMEOUT_MINUTES` (по умолчанию 30). Разрешение задаётся `VIDEO_RESOLUTION` (по умолчанию 2K — единственное разрешение, которое принимает текущая модель; проверено на проде).
- **Токены:** резервирование при запуске (`token_reservations`), окончательное списание один раз при успехе, возврат при ошибке/тайм-ауте. Повторные вызовы идемпотентны. Клиент видит баланс и зарезервированную сумму. Старые видео, списанные до этой схемы и завершившиеся ошибкой, возвращаются один раз автоматически.
- **История:** запросы, статус, результат и настройки хранятся на сервере и привязаны к аккаунту и проекту; изображения тоже сохраняются в `run_media`. У проектов в названии есть дата и время.
- **Формат изображения:** формат передаётся провайдеру (`size` + `aspect_ratio`), размер результата проверяется по байтам; при несовпадении запуск считается ошибкой и токены возвращаются.
- **Вход:** восстановление сессии, `?auth=login|register`, Forgot password (одноразовая ссылка на 60 минут, `/reset-password`), сохранение версии Terms и времени принятия, отдельный необязательный чекбокс рассылки (по умолчанию выключен), ссылки на Terms и Privacy.
- **Infini:** подробный серверный лог ответа провайдера и недостающих настроек (только имена), понятная ошибка при сбое открытия checkout, состояние «Loading payment methods». Причина прежнего «Something went wrong» по серверным логам и ключам **не установлена**: нужен доступ к логам Render и проверка INFINI_* на сервере.

## Не проверено / остаётся
Реальный провайдер видео и изображений (ID задания и формат ответа проверены только на mock), реальный Infini checkout и webhook, доставка писем (Resend) в проде, мобильная версия. Хранение видео в PostgreSQL подходит для небольших файлов; при росте объёма нужен объектный storage.

## Пункты 7–10 (2026-10-29)
- **Банковский перевод:** назначение платежа «Invoice <номер>», копирование IBAN, BIC, суммы и назначения, PDF с реквизитами (`/api/bank-transfer/documents?kind=requisites`), PDF инвойса; статус «Ожидает оплаты» / «Оплачен».
